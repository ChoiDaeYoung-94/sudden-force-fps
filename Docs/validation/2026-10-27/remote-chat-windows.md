#163의 PC 검증 범위에서 두 Player를 정상 UI로 조작했습니다. 방 참가 후 초안의 포커스 이탈, Enter·SEND 양방향 전송, 빈값·공백, 최대 길이, 재참가 후 전송을 확인했습니다. 제품 코드·프리팹 변경이나 새 빌드는 없습니다.

## 사용한 빌드와 방법

기존 Windows05의 360개 파일을 각 실행 전에 실제 SHA256으로 대조했습니다. EXE는 `9985CEA53B68F2D8787AAB4F496A228C335A139B39703A3915BEF6676716662A`, Game DLL은 `3D63D01B2F3932E22BE2F8D5AEB9160DA08E0ABD0EB93EDAA922FA0B1BF3AE9F`입니다.

소스는 P11 base `f055e4a84391bd9d8741c4e12855887b1ef72166`에 당시 UniRx·MENU·팝업 소스를 명시적으로 반영한 검증 빌드입니다. 바인딩 후보는 `910365c584d808ff922e3a8f2046cec2cb560b44`이며 최신 main 전체의 clean 빌드로 표현하지 않습니다. Draft PR261은 미포함입니다. 채팅 C# 두 개와 방 프리팹은 기존 빌드 입력 원장과 같고 현재 제품 소스와도 줄 끝 정규화 후 일치합니다.

1280×720 게임 창을 실제 닉네임과 고유 QA 방으로 구분했습니다. 각 창을 활성화하고 화면·포커스를 확인한 뒤 키보드 Return 또는 SEND를 한 번씩 입력했습니다. RPC·Submit 콜백 직접 호출과 런타임 eval 주입은 없었습니다. 처음 가려진 창 캡처가 다른 창처럼 보인 도구 관측은 활성화 후 재확인했으며 제품 실패·수신 증거에 포함하지 않습니다.

마지막에는 두 Player 모두 정상 방 나가기 후 EXIT GAME/OK를 한 번 입력했습니다. 실행 때부터 보유한 프로세스 handle로 각각 ExitCode0을 확인했고, 종료된 비공개 로그의 고정 `Crash!!!` 문자열은 각각0이었습니다. 종료 요청 뒤 창 조회·AltF4·강제 종료를 하지 않았습니다. 정확한 클릭 시각·종료 지연이나 모든 오류 부재를 측정한 것은 아니며 #154의 과거 종료 충돌 원인 해결로 합산하지 않습니다.
